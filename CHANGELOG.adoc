== v0.10.2.5 — 2026-07-29

* Move the CLI source from `bin/asciicrystal-kroki` to `src/cli.cr` so `shards build` no longer overwrites the source with the compiled binary; `main` now points to `src/cli.cr`.

== v0.10.2.4 — 2026-07-28

* Rename the shard `crystal-asciidoctor-kroki` → `asciicrystal-kroki` (drop the `crystal-` prefix, turn `doctor` into `crystal`).
* Rename the module `AsciidoctorKroki` → `AsciicrystalKroki`; the core namespace `Asciidoctor::` becomes `Asciicrystal::` via the `asciicrystal` dependency (formerly `crystal-asciidoctor`, `~> 2.0.26.12`).
* Restore the CLI source `bin/asciicrystal-kroki` (a compiled binary had been committed over it) and untrack the built artifact. Ruby-provenance mentions of the `asciidoctor-kroki` gem are preserved.

== v0.10.2.2 — 2026-04-22

* Fix compilation of the `crystal-asciidoctor-kroki` binary: add
  `require "html"` in `extension.cr`. The code was using `HTML.escape`
  without importing the stdlib `html` module, which went unnoticed
  because the CI only ran specs and the linter, never a full
  `shards build` of the binary target.

== v0.10.2.1 — 2026-04-22

* Add the *ameba* linter to the CI pipeline with a shared `.ameba.yml` config aligned with the Crystal ecosystem.
